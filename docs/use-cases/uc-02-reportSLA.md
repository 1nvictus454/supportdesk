# UC-02. reportSLA

**Актёр:** Руководитель смены.

**Цель:** Получить ежедневный отчёт по обращениям с просроченным SLA с разбивкой по логинам операторов, чтобы своевременно проработать причины просрочек с саппортами.

**Предусловия:**
1. В системе настроен ежедневный планировщик для формирования отчёта.
2. У руководителя смены указан корректный адрес электронной почты в профиле.
3. В системе есть данные об обращениях с рассчитанным SLA.

## Основной поток
1. **Система** по расписанию (например, в 09:00) запускает задачу формирования ежедневного отчёта по обращениям с просроченным SLA.
2. **Руководитель смены** ожидает поступления письма с отчётом на свою электронную почту.
3. **Система** собирает все обращения, у которых срок ответа по SLA истёк за отчётный период.
4. **Руководитель смены** открывает полученное письмо с отчётом.
5. **Система** группирует обращения по логинам операторов и рассчитывает процент обращений с просроченным SLA для каждого оператора.
6. **Руководитель смены** применяет фильтр по конкретному оператору для анализа.
7. **Система** отображает отфильтрованные данные по выбранному оператору с указанием процента просрочки.
8. **Руководитель смены** выгружает или сохраняет отчёт для дальнейшей проработки причин нарушений с саппортами.

## Альтернативы

А1 (к шагу 3). Обращений с просроченным SLA нет.
1. **Система** завершает сбор данных и обнаруживает, что обращений с просроченным SLA за период нет.
2. **Руководитель смены** ожидает поступления письма.
3. **Система** формирует и отправляет письмо с текстом: «Обращений с просроченным SLA нет».
4. **Руководитель смены** открывает письмо и убеждается в отсутствии обращений с просчроченным SLA.

А2 (к шагу 6). Руководитель хочет отфильтровать отчёт по нескольким операторам одновременно.
1. **Руководитель смены** выбирает в фильтре несколько логинов операторов.
2. **Система** объединяет данные по выбранным операторам и пересчитывает общий процент просрочки.
3. **Руководитель смены** просматривает сводные данные по нужным операторам.

## Исключения

И1 (к шагу 3). У руководителя смены нет прав на получение отчёта.
1. **Система** запускает задачу формирования отчёта по расписанию.
2. **Руководитель смены** ожидает получения письма.
3. **Система** проверяет права получателя и обнаруживает отсутствие доступа, после чего прерывает отправку.
4. **Руководитель смены** не получает письмо и обращается к администратору системы для выяснения причин.

## Постусловия
1. Руководитель смены получил на почту ежедневный отчёт по обращениям с просроченным SLA.
2. В отчёте доступен фильтр по логинам операторов и рассчитан процент просроченных тикетов.
3. При отсутствии просрочек руководитель смены получил письмо с текстом «Обращений с просроченным SLA нет».
